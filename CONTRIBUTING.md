# Contributing to Dutch Civic Cyber Resilience

Thank you for your interest in contributing! This project exists to make defensive security and emergency preparedness accessible to everyone in the Netherlands. 

We believe that **you do not need to be a software developer or cybersecurity expert to contribute.** Whether you want to report a new phone scam targeting your community, correct a spelling mistake, simplify a technical explanation, or translate our guidelines into another language, your contribution makes society safer.

---

## 1. Core Principles for Contributors

Before submitting content, please keep these three core guidelines in mind:

1. **Plain Language First:** Use simple, direct vocabulary. Avoid complex tech acronyms and corporate jargon. If an 80-year-old or a teenager cannot understand a step, it needs to be simplified.
2. **No Commercial Promotion:** We recommend free, built-in, or open-source tools. We strictly reject referral links, paid security software promotions, or corporate marketing.
3. **Inclusive & Safe:** Security is a human right regardless of income, origin, or language. Maintain a respectful and welcoming environment in all discussions.

---

## 2. How to Report an Issue (Simplest Method)

If you spot a mistake, discover a new scam operating in your area, or have an idea for a new guide—but you don't know how to edit files—**opening an Issue** is the best way to let us know.

<Sequence>
  <Step title="Go to the Issues tab">
    At the top of this GitHub repository page, click on the **Issues** tab.
  </Step>
  <Step title="Click 'New Issue'">
    Click the green **New Issue** button on the right side of the screen.
  </Step>
  <Step title="Write a clear Title and Description">
    - **Title:** Give a short, clear summary (e.g., *"New WhatsApp scam impersonating Dutch municipality workers"* or *"Typo in Pillar 1 Lockdown Mode section"*).
    - **Description:** Explain what you noticed, what needs changing, or what new information should be added.
  </Step>
  <Step title="Submit your issue">
    Click the green **Submit new issue** button at the bottom. A maintainer will read your note and help integrate it.
  </Step>
</Sequence>

## 3. How to Make Direct Edits or Add Translations (In Your Browser)

You do not need to install any command-line tools or programming software to edit files or add translations. You can do everything right inside your web browser.

### Scenario A: Editing an Existing File

1. Navigate to the file you want to improve (e.g., `pillars/01-mobile-security.md`).
2. In the top-right corner of the file view, click the **Pencil icon** (**Edit this file**).
3. Make your text edits directly in the browser window.
4. Scroll down to the **Propose changes** section at the bottom of the page:
   - Type a short note explaining what you changed (e.g., *"Simplified step 2 instructions for Android"*).
   - Click the green **Propose changes** button.
5. On the next screen, click **Create pull request**. This sends your proposed changes to the project maintainers to review and merge into the repository.

---

### Scenario B: Adding a New Translation File

We aim to make our framework available in community languages widely spoken across the Netherlands (e.g., Dutch, Ukrainian, Arabic, Turkish, Polish, Spanish).

To add a translation of an existing pillar:

1. Open the folder where the original file lives (e.g., the `pillars/` directory).
2. Click the **Add file** button in the top right and select **Create new file**.
3. Name your file using the language code prefix in the file name:
   - For a Dutch translation of Pillar 1: `pillars/01-mobile-security.nl.md`
   - For a Ukrainian translation: `pillars/01-mobile-security.uk.md`
   - For a Polish translation: `pillars/01-mobile-security.pl.md`
4. Paste your translated Markdown text into the main editor.
5. Scroll down, add a short title (e.g., *"Add Dutch translation for Pillar 1"*), and click **Propose new file**.
6. Click **Create pull request** to submit your translation for community review.

## 4. Markdown Formatting Guidelines

We use simple Markdown formatting to ensure all documents are clean and easy to scan:

- Use single `#` for main titles and `##` for section headings.
- Use simple hyphen bullet points (`- Item`) for un-ordered lists.
- Use square brackets for checklist items:
  - `- [ ] Task to be done` (un-checked box)
  - `- [x] Completed task` (checked box)
- Use standard blockquotes (`> Important note`) for crucial safety warnings.

---

## 5. Need Help?

If you get stuck or aren't sure if your contribution fits the framework:
- Open an **Issue** with the label `question` or `discussion`.
- Don't worry about making mistakes! Every submission goes through a friendly review process before it becomes public, so you can't break anything in the main project.

Thank you for helping keep Dutch communities safe, prepared, and resilient!
